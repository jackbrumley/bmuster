# SPEC-SHARE-LINKS: Short-lived links to one machine for someone without an account

**Status:** `IMPLEMENTED` except guest Files (section 8); version bump and changelog left for the release step · owner: "build everything", 2026-11-12 · design from `docs/access-and-sign-in.md` section 3 · **Date:** 2026-11-12

> **Security work** (AGENTS.md, "This tool controls other people's computers"). A share link lets someone with no account reach a machine's screen. It touches access, sessions, the session ticket and a new public page. The link is a narrower grant than its creator's own and the agent enforces the ticket as for any session. **By the owner's decision of 2026-11-12 (D1, D15) a guest connects without a consent prompt**, with the person at the machine always shown who is connected and able to disconnect them; section 7 records the residual risk.

## 1. Problem

An outside vendor needs to see (and sometimes drive) one computer, now, for an hour. Today the only way is an account, a group and a rule, which is slow and is left behind afterwards. MeshCentral's share links solve this; BMuster needs the same thing, treated like a key: short-lived, narrow, visible, revocable and audited.

## 2. What the design document decides (followed as written)

- Created from a machine's page by someone with `share-links` on that machine. Required: who it is for (free text), what it allows, how long.
- **What it allows:** _Watch desktop_ is always on; _Control desktop_ and _Files_ are tick boxes. Terminal is never offered. The creator can only tick what they hold on that machine.
- **How long:** 15 minutes, 1 hour, 4 hours, 8 hours, 24 hours. 24 hours is the maximum. _Changed by the owner on 2026-11-12: 48 hours and 7 days added, 7 days the maximum (D16)._
- Shown **once**, with a copy button. A 256-bit random token; the server stores only its hash.
- `https://<server>/s/<token>` opens a guest page: no console, the machine's desktop, a banner "Shared by <name> · ends <time>" and a countdown.
- **The person at the screen is always asked first** when someone is signed in, whatever the machine's rules say (SPEC-DESKTOP 7: share links always `ask`). _Deferred by the owner on 2026-11-12 until consent prompts exist: guests connect with the machine notified (D1, D15)._
- One guest session at a time per link. When the time runs out the link stops and any open session ends.
- The machine's page lists its active links (who for, what, created by, time left), each with **End now**, which also closes an open session. Admins see every active link in one list.
- Audit: created, opened (time, IP address, browser), session started and ended, each file transfer, ended early, expired.
- Wrong or expired tokens get the same plain "This link has ended" page; repeated failures from one address are rate-limited.
- Table `share_links`: id, machine_id, token_hash, recipient, permissions (json), created_by, created_at, expires_at, ended_at, ended_by.

## 5. Schema (additive, generated)

`src/lib/server/database/schema/share-links.ts`:

- `share_links`: `id` text PK; `machine_id` → machines; `token_hash` text unique; `recipient` text; `permissions` text (JSON list of `desktop-view`, `desktop-control`, `files`); `created_by` → users; `created_at`, `expires_at` (ms); `ended_at` (ms, null while active); `ended_by` → users (null when it expired or ended by itself). Index on (`machine_id`, `ended_at`).
- `share_link_failures`: `id`, `address`, `failed_at`; index on (`address`, `failed_at`). Rows older than a day are deleted when a new one is written.
- Added for D17 (migration `0020`, additive): `share_links.last_guest_name`, `last_guest_company`, `last_guest_address` (text) and `last_used_at` (ms), all null until the first guest session.

## 6. Routes

| Route                                 | Guard         | Does                                                                           |
| :------------------------------------ | :------------ | :----------------------------------------------------------------------------- |
| `GET /api/machines/[id]/share-links`  | `route.user`  | Active links on the machine (needs `share-links` there) and what may be ticked |
| `POST /api/machines/[id]/share-links` | `route.user`  | Create; replies with the link and its URL, once                                |
| `DELETE /api/share-links/[id=uuid]`   | `route.user`  | End now (needs `share-links` on the link's machine)                            |
| `GET /api/share-links`                | `route.admin` | Every active link                                                              |
| `GET /s/[token]`                      | `page.public` | Rate limit, resolve, set the guest cookie, audit "opened", the guest page      |
| `GET /s/[token]/status`               | `route.guest` | Still active and when it ends (the page polls it)                              |
| `POST /s/[token]/session`             | `route.guest` | Open the link's desktop session as `{ mode, name, company }` (D17)             |
| `POST /s/[token]/browser-ticket`      | `route.guest` | A fresh browser ticket for the link's own running session                      |

`route.guest` is a new guard: rate limit → token → guest cookie for the same link → link still valid (D2). The browser's socket is the existing `/api/sessions/[id]/socket?ticket=…`.

## 7. Security notes

- The guest never gets a console session, and guest routes never read the console cookie. A guest grant names one link, so one machine; every guest request re-resolves the link (expiry, end, creator's access).
- The ticket the agent receives names only the link's permissions, so the agent refuses input on a watch-only link exactly as for a member.
- The origin check (SPEC-SIGN-IN S8) covers every guest POST; the guest cookie is SameSite=Strict on top.
- Revocation is immediate: the row is ended and the relay ends the session in the same request.
- Nothing about other machines or people leaks: every refusal is the same plain page or `{ message }`.
- **Residual risk of D1/D15 (accepted by the owner, 2026-11-12).** Anyone holding a live link reaches the screen at once, with nobody at the machine agreeing first. A link forwarded, leaked from an inbox or chat, or seen over a shoulder gives its holder watch (and, on a control link, control) of the machine until someone notices the notice bar and presses Disconnect, the link is ended, or it runs out. With durations now up to 7 days (D16) that window is longer. What limits it: the notice cannot be turned off for guests (D1), the machine shows the guest's typed name and who shared the link, every session is audited with address and browser (D17), End now and Disconnect act at once, one session per link (D6), and the link carries only what its creator holds (D2). On an unattended machine (nobody in front of it) none of this is seen in time. Consent prompts (SPEC-DESKTOP phase 5) remove the risk; guests should be asked again once they exist.
- **Self-declared identity.** The guest's name and company are whatever they type; nothing checks them. They are labelled "says they are" for admins and never treated as an account. They are plain text on one line (no control characters, so no faked lines in the notice or Activity) and are rendered as text everywhere.
- **Client address** comes from `signInClient()`, as for sign-in: adapter-node reads `X-Forwarded-For` only when `ADDRESS_HEADER` is set and only at the trusted depth `XFF_DEPTH`, so a client cannot choose its own address (SPEC-HOSTING).

## 8. Not in this change

- **Consent prompts** (SPEC-DESKTOP phase 5). Until they exist, guests connect with the machine notified, by owner decision (D1, D15).
- **Guest Files panel.** The link records Files and the ticket carries it, but the guest page has no Files panel yet; the tick box is shown only once the panel exists. Its routes will be upload and download only, under `route.guest`, allowed while the link's desktop session is live (D14).
- Email notifications for share-link events (SPEC-EMAIL lists them as first events).

## 10. As built

- **The consent gate is one function**, `canAskAtScreen()` in `services/sessions/sessions.ts`, used by `ask` rules only. Guests do not pass through it (D1, D15): `guestDesktopTerms()` gives them consent `unattended` with the notice forced on, and `guest-sessions.test.ts` runs the real path with no mock.
- **Session records** carry `viewer: { kind: 'user' } | { kind: 'guest'; shareLinkId; sharedBy; identity; userAgent }`. A guest session's relay owner id is the link id, which gives one-session-per-link and browser tickets scoped to the link. Session audit entries for guests use the System actor and name the guest and the link. New end reason `share-link-ended`.
- **`SessionLink`** takes a `SessionRoute` (open URL, the open body, ticket request, storage key); `consoleSessionRoute()` gives the console's, and the guest page's adds the typed name and company to the open request. The guest page reuses `DesktopSession`, `DesktopCanvas`, `attachScreenInput`, `FullScreen` and `KeyBar` unchanged apart from that one constructor argument.
- **Admins' list** is a panel on the Access page; the machine's list is a panel on the machine's Overview, shown to people with `share-links` there.
- **Files:** the API accepts `files: true` (only from someone who holds `files`) and stores it, but the modal does not offer it and the guest page has no Files panel yet.
- **Notify-only guests, durations and guest identity (2026-11-12, owner decisions D15–D17).** `openGuestDesktop()` takes `{ mode, identity }` and the request's `SignInClient`; on success it also writes the link's last use. The audit detail for a guest session adds `says they are`, `company` (when given), `shared by` and `browser`. Activity's sentence comes from `activitySentence()` (`local-page-activity.ts`). The machine's Share links list shows "Last used by someone who says they are … from …, <time>" or "Not used yet". The guest page also offers copy and paste on a control link, and the local cursor (SPEC-DESKTOP 21, 22). Not changed: the agent, which already shows the notice for `unattended` tickets with `notice: true` and enforces the ticket's permissions; a long guest label (name, company and creator, up to about 200 characters) is shown as the agent's notice bar shows any name.
