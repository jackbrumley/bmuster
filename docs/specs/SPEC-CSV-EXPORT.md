# SPEC-CSV-EXPORT: CSV export on every list

**Status:** `IMPLEMENTED` (pending release: X1–X8 built, X9–X12 full machine detail built 2026-11-11; X13–X14 newly shown inventory built 2026-11-11; version bump and changelog left for the release step) · asked for 2026-11-07 · **Date:** 2026-11-07, full machine detail 2026-11-11

## 1. Problem

Admins need lists out of BMuster for audits, asset registers and outside parties: machines, users, groups, access rules and activity (`docs/concept.md`, Later). Copying from the screen is slow, and the Machines list only draws rows as you scroll. An export is also a way to take data out of the server, so it must respect the viewer's access and be audited like any other read of note.

## 5. Security notes

- Read-only, but it moves data off the server in bulk: the same access checks as the pages (`visibleMachineIds`, `activityScopeFor`, admin guards), never a browser-supplied list.
- The filters only narrow what the access check allows; no parameter widens it.
- **Full machine detail (X9–X12) is security work:** it moves a hardware and network inventory of every visible machine off the server. It exports exactly what the viewer could read on each machine's Overview tab and header, which needs `view` on that machine (checked by `visibleMachineIds`, the same access service the machine page uses). Groups stays admin-only (`canSeeGroups`). Nothing from the admin-only Manage tab (local page address and certificate, install and rejoin commands, the keep-awake setting and its state, logs, checks), no notes, and none of the raw inventory the page does not show (the display list, which the agent never fills). Since X13 (approved 2026-11-11) Overview, and so the export, also shows MAC addresses, graphics vendor and driver, uptime and the power source and battery level to anyone with `view`. Never secrets, keys, tokens, join codes or certificate material.
- Formula injection is guarded (X4); the file is served as an attachment with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.

## 6. Open questions

1. Activity has no search, filter or date range on the page today. The export takes `from` and `to` so a later filter bar can pass them through; the button exports everything the viewer may see, newest first, up to the cap. Should Activity get a date-range picker?
2. Users, Groups and Access rules have no search, filter or sort on screen, so their exports follow the page order.

**Different from the spec or decided while building**

- **Machines columns.** OS is the reported name ("Ubuntu"), or the family before the first inventory; OS version is empty until then. CPU % and Memory % are filled only while the machine is online, as on screen. Groups leaves out All machines, which holds every machine.
- **Groups.** One file, groups of people first, then groups of machines (All machines first). Members are listed by name.
- **Activity details.** Every detail except `ip` goes in Details as `label: value`. A member's Activity export holds the same entries as their Activity page, which includes group membership changes about their machines (so a group name can appear there).
- **Full machine detail (2026-11-11, X9–X12).** One row per machine still. The page's `gpuLabel` moved from the Overview route to `domain/machines/machine.ts`, and the Display card's report-to-facts switch to `displayFacts` in `domain/machines/display-report.ts`, so the page and the export share them. Agent update is the header badge's label, "Up to date", or empty when the server has no signed build to compare with. Signed in is the person's name, "Nobody", or empty before the first check-in. In use follows the Overview ("terminal by Ada, desktop (control) by Pat"). Pending updates is a number (0 is up to date; empty when not reported). Memory used and Memory total are formatted like the page ("1.0 KB", "16.0 GB"). Display holds the Display card's facts as `label: value`, empty when the agent does not report them. Relative times on screen ("5 min ago") are ISO times in the file.
- **Query errors** answer 400 with the first problem, like the JSON routes.
- **Newly shown inventory (2026-11-11, X13–X14).** Four columns after Display, built from the Overview's helpers (`formatDuration`, `powerSourceLabel`, `gpuItem`, `adapterItem`) so the cell reads as the screen does. Graphics and Addresses keep their meaning (now shown in the Graphics and Network cards). Uptime is counted on from the last check-in, like the page.
