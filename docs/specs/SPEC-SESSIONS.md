# SPEC-SESSIONS: Terminal sessions (first remote session type)

**Status:** `IMPLEMENTED` (T1–T8; version bump and changelog left for the release step) · approved 2026-11-07 · Desktop and file sessions follow in later specs and reuse this relay.

## 1. Problem

BMuster can see machines but cannot do anything on them. A terminal is the cheapest real remote-control feature and proves the session path: browser ⇄ server relay ⇄ agent, with server-signed tickets the agent checks.

## 3. Agent

- Linux/macOS: a PTY (`openpty` / `forkpty` via `libc`, or the `portable-pty` crate, pinned) running the shell as root with `TERM=xterm-256color`; resize via `TIOCSWINSZ`.
- Windows: ConPTY (`CreatePseudoConsole`) via the `windows` crate or `portable-pty`; checked with the Windows clippy target.
- Messages on the session socket: binary frames are terminal bytes; text frames are JSON control (`resize`, `exit`).

## 4. Later

Consent prompts and the on-screen notice arrive with desktop sessions; the exec action for MCP reuses the ticket and relay.

**Different from the spec or decided while building**

- **Reloads.** Closing the tab does not end the session at once: the browser has 60 s to come back (the page keeps the session id in `sessionStorage`, per tab) and the server replays the last 256 KB of output. Raw replay into a terminal of another size can show garbled lines that the shell redrew at the old size.
- **Phones.** Below 900px the terminal runs edge to edge (it undoes the page gutter, `--page-gutter`, and the safe-area padding; its text keeps clear of a notch). A swipe on it scrolls the history with momentum, never the page (`touch-scroll.ts`, `terminal-touch.ts`); a tap still focuses it. In the alternate screen (vim, less, htop) each row of a swipe is a wheel event for xterm.js, which sends arrow keys or mouse-wheel reports, without momentum. A finger that rests before moving is left to the browser (long-press). Tests: `touch-scroll.test.ts`, `terminal.svelte.test.ts`.
- **One browser per session.** A second window takes the session over; the first is told and can take it back.
- **No database table.** Running sessions live in the server's memory (they end with the process anyway); the audit log is the record.
- **Exec sessions** (`purpose: exec`, permission `ai-commands`) are built in the agent with tests (`exec/pipe.rs`: no input, separate stdout and stderr frames, time limit up to 10 min, output cap up to 16 MB). The server issues none yet; MCP comes later (docs/mcp.md).
- **Consent** (`ask` rules) is not enforced for terminals yet; it arrives with desktop sessions.
- **Socket routes** carry binary frames, take `[name]` path parameters and can pause reading. Files will reuse the ticket (a new `files` purpose), both sockets, the relay and the agent's pump.

### T10 as built (v0.4.20, 2026-11-12)

- **Cause.** A resize the browser sent before the agent's session socket was open was dropped by the relay (it forwarded only to a connected agent), so a phone turned while the shell started kept the portrait width. On Windows, xterm.js also reflowed lines that ConPTY redraws itself, leaving stale line breaks.
- **Relay.** `relay.ts` keeps `lastResize` per session and sends it to the agent first when it attaches, before any early input; later resizes go straight through.
- **Page.** `terminal-session.svelte.ts` already sent the latest size again on every `attached`, so a resize lost while reconnecting was never lost for good; it is unchanged, and `terminal-session.svelte.test.ts` now guards that. The host's ResizeObserver sees a turn (the test turns a 390 by 844 viewport to 844 by 390 and checks a wider `resize` goes out), so no extra viewport listener was added.
- **Windows.** `windows-pty.ts` gives xterm.js `{ backend: 'conpty', buildNumber }`, the build read from the inventory's OS build (the last number of 10000 or more), else 17763 (the first ConPTY build). Below build 21376 xterm.js then leaves reflowing to ConPTY.
- **Not tested here:** a real phone turning, and ConPTY's redraw on Windows (no Windows machine).

**Not tested here:** ConPTY and SYSTEM shells (no Windows machine); running as root (the end-to-end agent ran as the developer).
